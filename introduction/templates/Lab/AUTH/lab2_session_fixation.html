💀 How Session Fixation Works
  1. Setup: Attacker obtains a valid session ID from the application
  2. Fixation: Attacker tricks user into using this session ID (via email, URL, etc.)
  3. Authentication: User logs in using the attacker's session ID
  4. Hijacking: Attacker uses the known session ID to access user's account
🛡️ Prevention Measures
  • Session Regeneration: Generate new session ID after successful login
  • Session Validation: Verify session ownership and integrity
  • Secure Cookies: Use HttpOnly, Secure, and SameSite flags
  • Session Timeout: Implement appropriate session expiration
📝 Vulnerable vs Secure Code
❌ Vulnerable Code:
# Accepts external session ID
session_id = request.POST.get('session_id') or generate_session()
# No regeneration after login
session = Session(id=session_id, user=user)
✅ Secure Code:
# Always generate new session after login
old_session_id = request.session.session_key
request.session.cycle_key()  # Regenerate session ID
new_session_id = request.session.session_key
🔍 Real-World Attack Scenarios
📧 Email Attack

🌐 Cross-Site Attack

Malicious website sets session cookie before redirecting to legitimate site

📱 Physical Access

Attacker with physical access sets session ID on public computer
