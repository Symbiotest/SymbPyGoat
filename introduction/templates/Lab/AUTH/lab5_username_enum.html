💀 How Username Enumeration Works

Information Disclosure Methods:

  • Different Error Messages: "Invalid username" vs "Invalid password"
  • Timing Attacks: Different response times for valid/invalid users
  • HTTP Response Codes: Different status codes for different scenarios
  • Application Behavior: UI changes based on username validity

Attack Process:

  1. Test common usernames against the application
  2. Analyze response patterns and timing
  3. Build a list of valid usernames
  4. Use enumerated usernames for targeted attacks
🛡️ Prevention Techniques

Consistent Response Design:

  • Generic Messages: "Invalid credentials" for all failures
  • Constant Timing: Same response time regardless of validity
  • Identical HTTP Codes: Same status codes for all auth failures
  • Rate Limiting: Prevent automated enumeration attempts

Additional Measures:

  • CAPTCHA after failed attempts
  • Account lockout policies
  • Monitoring and alerting
  • Multi-factor authentication
⏱️ Timing Attack Analysis

This lab implements deliberate timing differences to demonstrate timing attacks:

❌ Vulnerable Timing:
  • Valid Username: ~100ms delay (password processing)
  • Invalid Username: ~0ms delay (immediate response)
  • Pattern: Timing reveals username validity
✅ Secure Timing:
  • All Requests: Same processing time
  • Implementation: Always perform full authentication check
  • Pattern: No timing information disclosed
